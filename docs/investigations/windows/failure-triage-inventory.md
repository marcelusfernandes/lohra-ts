# Inventário residual Windows por teste e Node (#751)

Medição **nativa** de `main` em `ebeb722f898bdb4cde5b7d7cef66fb40febf5c15`, após a integração de #794, no Windows 11 x64 (`10.0.26200`). Git `2.47.1.windows.1`; Node 20.20.2/npm 10.8.2 e Node 22.23.2/npm 10.9.8. Cada Node usou um clone Git padrão independente, checkout detached conferido e `npm ci` de sua própria ABI. `core.protectNTFS` não recebeu override; `core.autocrlf=true` veio da configuração de sistema do Git. Home, Lohra/Codex home, cache e temporários foram isolados em F:. O [procedimento](evidence/failure-triage/inventory/procedure.md) preserva comandos, limites e as [fontes](evidence/failure-triage/inventory/source.md) das sondas. A SHA desta documentação será posterior e não substitui a SHA medida.

Os campos de assertions reconciliam integralmente com o JSON do Vitest em ambos os Nodes, incluindo o caso pendente. `numTotalTestSuites` conta agrupamentos e **não** equivale aos 336 `testResults` de arquivos. As [metadatas Node 20](evidence/failure-triage/inventory/metadata-node20.json) e [Node 22](evidence/failure-triage/inventory/metadata-node22.json) registram os exits, duração, SHA-256 dos logs brutos e resultado das verificações de conciliação. Os logs integrais e JSONs brutos ficam somente em F:, identificados por esses hashes; o repositório contém as projeções sanitizadas de [arquivos 20](evidence/failure-triage/inventory/files-node20.jsonl), [arquivos 22](evidence/failure-triage/inventory/files-node22.jsonl), [falhas 20](evidence/failure-triage/inventory/failures-node20.jsonl) e [falhas 22](evidence/failure-triage/inventory/failures-node22.jsonl). Cada falha tem ID estável derivado de arquivo+teste, mensagem primária, assinatura e, quando presente, mensagens secundárias ordenadas.

As maiores **assinaturas**, sem atribuição de causa comum, foram `EBUSY unlink` (77/79 assertions Node 20/22), `expected null to be 2` (32/32), `expected null to be +0` (27/27) e `ENOENT lstat` (13/13). Há 58 assinaturas primárias distintas no Node 20 e 59 no Node 22; frequência de texto não significa número de bugs. Em cada Node, 17 assertions têm segunda mensagem, preservada sem inflar o total de falhas: 16 `unlink state.db` e uma `rmdir lohra-eval-session-test-<RANDOM>`. Uma falha de cleanup pode ser secundária à asserção primária; a ordem no reporter foi conservada e a causalidade requer sonda focal. Três falhas do `tests/parity/stub-driver.test.ts` que começavam apenas como `AssertionError:` trazem no corpo o diagnóstico `ERR_MODULE_NOT_FOUND`, agora preservado na mensagem primária sanitizada.

A [comparação](evidence/failure-triage/inventory/comparison.json) por ID mostra 229 testes falhos comuns, nenhum exclusivo do Node 20 e três exclusivos do Node 22: dois `EBUSY` em `tests/gateway/session-service.test.ts` e uma asserção de exit 3 esperado versus 1 em `tests/mutations-all.test.ts`. Onze testes comuns têm assinaturas de mensagem diferentes. Isto é divergência observada neste ensaio, ainda sem causa atribuída. `tests/workflow-service-durability.test.ts` passou 34/34 em ambos; #787 continua uma correção de fixture pendente/bloqueada, mas o inventário **não** sustenta atribuir a ela os demais `EBUSY`.

O JSON bruto do reporter não expôs `unhandledErrors`, portanto seu estado é **NOT_REPORTED**, e não “zero erros”. O stderr contém sete [diagnósticos Node 20](evidence/failure-triage/inventory/stderr-node20.jsonl) e sete [Node 22](evidence/failure-triage/inventory/stderr-node22.jsonl): avisos `ELOOP` de caminhos/skills e shadowing MCP, sem ID de teste. Foram registrados à parte, sem contá-los como assertions ou afirmar que são unhandled. Falhas de setup/timeout foram **não observadas** no ensaio válido; provider live, causa-raiz de cada assinatura e suporte Windows permanecem **NOT_MEASURED**. Duas tentativas anteriores do helper pararam antes da suíte por leitura nula de `git status` vazio, foram corrigidas e constam apenas no procedimento, nunca nas contagens.

As reproduções mínimas de `serve`/compactação em #752 e de permissões/sinais/cleanup em #753 devem partir dos IDs deste inventário. Elas não cobrem automaticamente todas as 229/232 falhas. A síntese #754 deve dar a cada remanescente uma família comprovada ou `INCONCLUSIVE` com próximo experimento; não converter as 366 assertions históricas de W2 em 366 bugs nem abrir duplicata de #787 sem evidência focal.
