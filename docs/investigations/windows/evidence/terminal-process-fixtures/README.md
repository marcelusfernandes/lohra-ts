# #848 — fixtures de processo do terminal

O teste focal `tests/tools-local.test.ts` executa o terminal/PTY real. A base `342a839` entregava comandos POSIX literais a `cmd.exe` no Windows; Node 20.20.2 e 22.23.2 falharam nos mesmos 3 de 20 casos: `printf` não reconhecido no contrato de `out`/`err`/exit 7, `sleep` não reconhecido no timeout `2.50` e stdout vazio no timeout `null`. As outras cinco expectativas de timeout passavam sem demonstrar que o comando tinha iniciado. No commit vermelho `e597ce2`, uma asserção de marcador de início para `2.50` falhou nas duas ABIs com `existsSync(started) === false`; o arquivo continuou compilando (`npm run typecheck` exit 0).

No commit verde `57f0d6c`, cada caso cria um script Node temporário com **espaços no nome**, invocado por `process.execPath` entre aspas apropriadas ao shell da plataforma. Node 22 usa `C:\Program Files\nodejs\node.exe` e exercita também espaço no caminho do executável; o Node 20 portátil usa seu executável próprio no drive F. O caso de saída chama `stdout.write("out")`, `stderr.write("err")` e `exit(7)`, preservando a comparação exata do envelope. O caso `null` emite `ok`. A fixture de timeout registra `terminal-child-started` e encerra naturalmente após 4000 ms se não for interrompida; o caso `2.50` exige o marcador antes de aceitar a mensagem de timeout. Para os outros lexemas, a fixture tem comando válido, mas um deadline curto (especialmente `0`) pode terminar antes de o script iniciar, portanto não afirmamos que cada filho começou.

A matriz `it.each` conserva os **nomes históricos** com `sleep 4` para não quebrar o inventário, mas a string entregue a `terminalTool` é substituída pelo comando Node da fixture. Apenas o valor JSON de `command` é trocado; `1`, `1.0`, `2.50`, `1e0`, `true` e `0` continuam literalmente presentes no texto recebido por `parseToolArguments`. Os testes de política de comando perigoso, filesystem, recusas e 50.000 code points por stream não foram enfraquecidos. O script de Unicode também usa `process.execPath`, sem depender de `node` no PATH.

As chamadas usaram clones separados com dependências da mesma ABI, homes/caches/temporários próprios e `npm ci` do lock. Os scripts têm espera finita de 4 s; o teste não encerra processos por PID ou nome. `afterEach` removeu as fixtures próprias sem erro nos focais/provas, mas isso sozinho não prova ausência universal de descendentes; a questão de lifecycle do PTY é coberta por testes específicos do terminal.

A prova declarada retornou `ok:true`, `total:20`, `falhas:[]`. O controle negativo saiu 0 com **SKIP mecânico test-only**: diff apenas em `tests/**` e `prova/**`; não é um resultado `assertion-red`. O vermelho nativo `e597ce2` é a evidência discriminante. Logs e `resumo.json` do Linux estão em `F:/lohra-m25-848/linux-evidence/`.
